# Contributing

Thanks for taking the time to contribute to a Porma Software repository.

## Workflow

1. Open an issue first for anything beyond a typo fix, so scope is agreed before code is written.
2. Branch from `main` using `feat/<short-name>`, `fix/<short-name>` or `chore/<short-name>`.
3. Keep commits small and descriptive. Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`) are preferred.
4. Every change ships with tests. CI must be green before review.
5. Open a pull request using the template. One reviewer approval is enough.

## Code standards

- Code, comments and technical docs are written in English.
- Minimal comments: explain *why*, not *what*.
- No secrets in the repository. Use `.env.example` and keep `.env` ignored.
- Public APIs and behaviour changes must be reflected in the README.

## Licensing

Every Porma Software repository is proprietary (see its `LICENSE`): all rights reserved, no
public contributions accepted without a prior written agreement with the copyright holder.
The only planned exception, not in effect today, is a possible public portfolio repository,
which would carry the MIT license if it is ever published.
